## 这一章你要带走什么

能用自己的话画出一条线：**任务 → 分支 → 改代码 → 自测 → PR → 评审 → 合并 → 发布**。

## 主路径（文字版）

1. 读懂任务与验收标准（含设计稿链接）
2. 从默认分支拉出短生命周期分支
3. 在约定目录改最小可演示增量
4. 本地自测 + 设计还原检查
5. 推送并开 PR（描述、截图/预览、自检清单）
6. 根据 Review 修改并回复
7. CI 绿、批准后合并；关注发布/验证

## 为什么先看地图

没有地图时，初级容易在「先学完美架构」或「直接猛写」两端摇摆。地图规定**顺序**：先能合入，再谈抽象。
